# Release 2.5.0 — Story Index

## Theme

**Start from the customer's document: import their design and get the whole mapping proposed from the connected source, then review and fine-tune it.**

- **Whole-mapping proposal** — Import a JSON design (one or several files) and the tool picks the driving table, the related table behind every embedded object and array, and the column, conversion or constant behind every field, all read from the connected source
- **Both directions, any depth** — Embeds from References and Referenced by, 1:1 tables folded onto the parent, two levels down and deeper, with close alternatives offered
- **Uses what the design says** — Constants, enums, "sourced from table.column", "Not populated" and the document ID pattern are evidence, not noise
- **Review on the customer's structure** — Every proposed binding and field with its confidence and reasons, on the design's own tree; fine-tune with the editors you know; apply in one step
- **Safe on existing work** — If the table is already mapped, you're asked first: update that mapping (with a diff), create a separate one (with a key-overlap warning) or cancel
- **Variant shapes** — Arrays and objects whose items take one of several shapes (`oneOf`, or several design files), each built from its own table: by which key is set, by a type column, or as a union of child tables
- **Version you can quote** — Every page, export and `odb --version` shows the release (2.5.0) and the build
- **Canvas usability** — Both ends of a mapping in view at once, and source columns in the document's order
- **Open source** — Apache-2.0: every artifact carries its license and its dependencies' notices, and CI keeps copyleft out
- **Run with odb alone** — No more migrate.sh: the same export folder runs on macOS, Windows and Linux with the same `odb preflight` and `odb run` (or one Docker command); odb is signed so it opens with no warning on Mac and Windows

## Release checklist

- [ ] All P0 stories are Implemented (and P1 stories are Implemented or explicitly descoped with sign-off)
- [ ] CI green on `main`: lint, unit, integration (including the `pos` seed), contract, E2E (`design-first.spec.ts`)
- [ ] Proposal quality gate G10 and the propose benchmark pass on the reference environment; results committed under `bench/results/2.5.0/` (OC-173)
- [ ] No customer files in the repository: fixtures are generic and synthetic (OC-162)
- [ ] `VERSION` says 2.5.0, the tag matches, and the footer, `odb --version` and exports show it (OC-172)
- [ ] 2.0 bundles still run on 2.5 `odb`; 2.5 bundles with variants are refused by 2.0 `odb` with `SPEC_FEATURE_UNSUPPORTED` (OC-171)
- [ ] User guide *Start from the customer's design* and release notes published
- [ ] The same 2.5 export folder runs with `odb preflight` and `odb run` on macOS, Windows and Linux (no migrate.sh); a 2.0 export still runs, with its migrate.sh (odb 2.0) or with odb 2.5 in its folder (OC-182, OC-184)
- [ ] The macOS odb is universal, Developer ID–signed and notarized; a quarantined download runs with no Gatekeeper prompt on Intel and Apple silicon (OC-185); odb.exe is Authenticode-signed and runs with no SmartScreen prompt (OC-186)
- [ ] Apache-2.0: LICENSE, NOTICE and headers in place; `make licenses-check` green; the image, odb archives and the app carry the licenses; full-history secret scan clean before the repository is public (OC-189)
